# Build Guide

This guide covers everything needed to build THAIME from source, including the dictionary pipeline, WASM target, and web demo.

## Prerequisites

| Tool | Version | Purpose |
|------|---------|---------|
| [Rust](https://rustup.rs/) | stable | Core toolchain |
| `curl`, `gunzip`, `sha256sum` | any | Data fetch (`scripts/fetch-data.sh`) |
| [wasm-pack](https://rustwasm.github.io/wasm-pack/) | latest | WASM build (optional) |
| [Node.js](https://nodejs.org/) | 22+ | Web demo (optional) |

## Quick Start

```bash
# Fetch the pinned NLP data and compile the dictionary (once per data version)
./scripts/fetch-data.sh

# Build everything (debug)
cargo build --workspace

# Run tests (includes the regression snapshot)
cargo test --workspace

# Run the CLI
cargo run -p thaime_cli

# Run the TUI
cargo run -p thaime_tui
```

Dictionary and n-gram binaries are not committed (`data/dict/*` and `data/input/*` are
git-ignored). The engine embeds the dictionary at compile time, so `cargo build` fails
until `fetch-data.sh` has run.

## Data Fetch

`scripts/fetch-data.sh` reads `thaime-data.toml` for the pinned
[thaime-nlp](https://github.com/mimocha/thaime-nlp) release and checksums, then:

1. Downloads `trie_dataset.json.gz` and the n-gram binary from the public GitHub
   Release with `curl` (no GitHub login needed) into `data/input/`
2. Verifies the pinned SHA-256 checksums and decompresses
3. Compiles the dictionary with `thaime_dictgen` into versioned files in `data/dict/`
   (e.g. `trie-v1_0_0.bin`, `metadata-v1_0_0.bin`, `thaime-v1_0_0.dict`)

To use local artifacts instead (e.g. fresh output from thaime-nlp), point
`THAIME_DATA_DIR` at a directory with the uncompressed files; see
[`data/README.md`](../data/README.md).

## Web Demo Build Pipeline

`scripts/build-web.sh` prepares the web demo after `fetch-data.sh`:

```
Step 1/3: Build workspace (release)
    └─ cargo build -r --workspace

Step 2/3: Build WASM package
    └─ wasm-pack build crates/thaime_wasm --target web

Step 3/3: Copy dict + ngram to web demo
    └─ Copies thaime-<vtag>.dict and the pinned n-gram binary to web/public/dict/
    └─ Writes web/.env with VITE_DICT_FILE and VITE_NGRAM_FILE
```

## Regenerating Data Locally

The dictionary source data (`trie_dataset.json`) is generated by the companion [thaime-nlp](https://github.com/mimocha/thaime-nlp) repository. To test unreleased pipeline output, run the pipeline there and fetch from the output directory instead of the release:

```bash
# In the thaime-nlp repo:
python -m pipelines trie run

# In thaime:
THAIME_DATA_DIR=/path/to/artifacts ./scripts/fetch-data.sh
```

`fetch-data.sh` runs the `thaime_dictgen` crate, which compiles the JSON into binary files:

```bash
cargo run -r -p thaime_dictgen -- data/input/trie_dataset.json data/dict/ --version-tag v1_0_0
```

This produces three files in `data/dict/`:

| File | Contents |
|------|----------|
| `trie-<vtag>.bin` | yada double-array trie (romanization keys → group IDs) |
| `metadata-<vtag>.bin` | bincode-serialized word metadata + CSR posting lists |
| `thaime-<vtag>.dict` | Combined blob for WASM (`[4B trie_len][trie][metadata]`) |

The build script (`crates/thaime_engine/build.rs`) discovers these files and sets `THAIME_TRIE_PATH` and `THAIME_METADATA_PATH` environment variables so they are embedded at compile time via `include_bytes!()`. It prefers versioned filenames matching the `thaime-data.toml` version (e.g., `trie-v1_0_0.bin`) and falls back to unversioned names (`trie.bin`, produced when `--version-tag` is omitted).

## N-gram Binary

N-gram language model binaries are generated from the [thaime-nlp](https://github.com/mimocha/thaime-nlp) repository:

```bash
# In the thaime-nlp repo:
python -m pipelines ngram run

# Copy output to thaime:
cp pipelines/outputs/ngram/thaime_ngram_v1_mc*.bin /path/to/thaime/data/input/
```

Multiple variants with different `min_count` thresholds can be generated (e.g., `mc10`, `mc15`, `mc20`); releases ship one. Higher min_count means fewer but more reliable n-gram entries. The build script uses the file pinned in `thaime-data.toml` and falls back to the highest available min_count variant; `scripts/build-web.sh` copies only the pinned file.

File naming convention: `thaime_ngram_v{format_version}_mc{min_count}.bin`

### Loading Modes

N-gram data can be loaded in several ways:

| Mode | How | When |
|------|-----|------|
| Embedded | `embed-ngram` feature flag | Compile-time embedding via `include_bytes!()` |
| Runtime (binary) | `--ngram-bin <path>` (CLI) | Load pre-built binary at startup |
| Runtime (TSV) | `--ngram-dir <path>` (CLI) | Load raw TSV count files (dev/debug) |
| Auto-discover | Default CLI behavior | Scans `data/input/` for binary, falls back to TSV |
| Hot-load (WASM) | `WasmEngine::load_ngram()` | Fire-and-forget after page load |

## Feature Flags

| Feature | Default | Description |
|---------|---------|-------------|
| `embed-dict` | **yes** | Embed dictionary binaries at compile time |
| `embed-ngram` | no | Embed n-gram binary at compile time |

```bash
# Build with both features
cargo build --features embed-ngram

# Build without embedded dictionary (for runtime loading)
cargo build --no-default-features
```

## Build Artifacts

| Artifact | Path | Description |
|----------|------|-------------|
| CLI binary | `target/{debug,release}/thaime_cli` | Interactive REPL |
| TUI binary | `target/{debug,release}/thaime_tui` | Visual debugger |
| WASM package | `crates/thaime_wasm/pkg/` | wasm-bindgen JS+WASM bundle |

## WASM Build

Requires `wasm-pack` and the `wasm32-unknown-unknown` target:

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-pack

wasm-pack build crates/thaime_wasm --target web
```

Output goes to `crates/thaime_wasm/pkg/`, which the web demo's `vite.config.ts` references.

## Web Demo

The web demo is a React + TypeScript application in the `web/` directory:

```bash
cd web
npm install
npm run dev     # Development server
npm run build   # Production build → web/dist/
```

The demo needs dictionary and n-gram files in `web/public/dict/`. `scripts/build-web.sh` (step 3) handles this, or you can copy them manually:

```bash
mkdir -p web/public/dict
cp data/dict/thaime-v1_0_0.dict web/public/dict/
cp data/input/thaime_ngram_v1_mc15.bin web/public/dict/
echo 'VITE_DICT_FILE=thaime-v1_0_0.dict' > web/.env
echo 'VITE_NGRAM_FILE=thaime_ngram_v1_mc15.bin' >> web/.env
```

## CI/CD

Two GitHub Actions workflows are configured:

### CI (`ci.yml`)

Runs on pushes and PRs to `main` and `dev`:

1. License header check (hawkeye)
2. Format check (`cargo fmt --all -- --check`)
3. Fetch data (`scripts/fetch-data.sh`)
4. Clippy lint (`cargo clippy --all-targets --all-features -- -D warnings`)
5. Build (`cargo build --workspace`)
6. Test (`cargo test --workspace`), including the regression snapshot
   (`crates/thaime_engine/tests/regression.rs` over `tests/harness-regression.toml`)

### Deploy Web Demo (`deploy-web.yml`)

Runs on push to `main` (and manual dispatch):

1. Fetch data (`scripts/fetch-data.sh`)
2. Build WASM and copy the versioned dictionary + n-gram to `web/public/dict/`
   (`scripts/build-web.sh`)
3. Build Vite production bundle
4. Deploy to GitHub Pages
